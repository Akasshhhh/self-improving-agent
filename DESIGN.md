# Design note

This take-home keeps the probabilistic model outside the authoritative scheduling boundary. The model can ask to search, book, list, or cancel; Pydantic validates its arguments, the dispatcher supplies the trusted session patient identity, and the repository applies the operation in SQLite. The database transaction and unique active-slot index decide whether a booking exists. A model response saying “confirmed” is not treated as evidence of a booking.

Conversation state is in memory for one CLI process. Appointment state is durable in SQLite. Each run produces a JSON trace with policy/agent versions, messages, tool calls and arguments, tool results/errors, and final appointment state. This separation makes traces useful for evaluation without allowing them to become a second source of truth. Redis was omitted because the single-process demo does not need shared session state; a multi-worker service could use Redis for short-lived active context while retaining durable records in a database.

Evaluation uses ten scripted scenarios and deterministic checks over database outcomes and trace events. A case passes only if every check passes; the aggregate is the case pass percentage. The ambiguous “that one” case fails under v1 and passes under v2. A structured proposal is schema-validated, and deterministic promotion requires target improvement with no previously passing case regressing. The default proposer and scenario model are scripted for repeatability. They demonstrate the evaluation and promotion mechanics, not general LLM improvement. The live CLI uses an OpenAI-compatible model adapter; `--live-proposer` can use that adapter to generate a proposal.

No LLM judge is used in this version. The finite scenarios have explicit assertions, and a transcript-only judge cannot inspect SQLite or verify tool side effects. If added, a judge should score conversational clarity only; deterministic checks remain responsible for safety and booking correctness.

AI tools helped scaffold and implement the repository. Engineering judgment overrode generated breadth in favor of a small SQLite-backed design, trusted session identity, deterministic acceptance gates, and a disclosure that scripted before/after behavior is simulated. The demo assumes synthetic patient data and a trusted local CLI identity; it is not a production authentication or privacy design.
